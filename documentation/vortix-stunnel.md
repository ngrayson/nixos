# Vortix + Stunnel (Declarative)

This repo declaratively manages Vortix and the FrootVPN stunnel client.

## Source of truth

- System module: `common/vpn-vortix.nix`
- Canonical OpenVPN profiles: `vpn/ovpn/`
- User path generated by Home Manager: `~/.config/ovpn`

## Stunnel integration contract

- `services.stunnel.clients.frootvpn` listens on `127.0.0.1:1194`.
- It forwards to `ca-west.frootvpn.com:443` and validates TLS with `/etc/frootvpn/stunnel-ca.pem`.
- Any profile intended for this integration must target `127.0.0.1 1194` in its remote endpoint.

## Vortix usage

- Generic entrypoint: `vpn` (`sudo vortix`)
- Stunnel-aware entrypoint: `vpn-froot` (checks `stunnel.service` before launching Vortix)
- Desktop launcher: `VPN (Vortix)` uses `vpn-froot`

## Updating provider files

1. Place or update `.ovpn` files in `vpn/ovpn/`.
2. Rebuild: `sudo nixos-rebuild switch`.
3. Open a new shell and import/refresh profiles in Vortix as needed.

## Rotating stunnel CA file

1. Replace `frootvpn-stunnel-ca.pem` at repo root.
2. Rebuild: `sudo nixos-rebuild switch`.
3. Verify `/etc/frootvpn/stunnel-ca.pem` points to the new certificate.

## Verification checklist

Run after rebuild:

```bash
command -v vortix
systemctl status stunnel.service
ss -ltnp | rg 1194
vpn-froot
```

Then connect/disconnect a stunnel-backed profile in the Vortix UI.
